# Pre-alpha release and farm01 rollout

Remote commands are `./scripts/bazel test //:acceptance` and `./scripts/bazel build //:release_artifacts`. The packages include static `agentboard` binaries for Linux/Darwin amd64/arm64, CLI SHA256SUMS, the OTP release archive, and the Linux amd64 dashboard OCI layout/digest. Linux amd64 executes natively; Linux arm64 executes with pinned QEMU on the remote amd64 executor. Darwin runtime execution is untested. Dashboard runtime uses pinned Ubuntu Noble, UID/GID 10001, release state under `/tmp`, and disabled Erlang distribution. Kubernetes supplies readOnlyRootFilesystem and writable bounded `/tmp`.

BuildBuddy's `buildbuddy.yaml` runs the real acceptance targets and packages. Configure its `BUILDBUDDY_API_KEY` secret/environment; `scripts/ci-bazelrc` writes only a gitignored credential file without logging the key. GitHub's manual release workflow uses the same remote targets, then pushes the verified OCI digest to Harbor and creates a **draft** GitHub release with binaries/checksums/release archive/image reference and the matching Kustomization. It accepts only an existing `v0.1.0` tag whose commit is on main. Configure protected `agentboard-release` environment and BUILDBUDDY_API_KEY, HARBOR_USERNAME, HARBOR_PASSWORD secrets first. The operator provisions release environment secrets out of band; never record their values in Git. Pin updates and credential provisioning are separate operator actions.

The application and migration Job must reference the same `registry.carverauto.dev/agentboard/dashboard@sha256:...` digest. Release automation emits the overlay's image setting with that digest; commit it through the deployment review before rollout. A local build digest is not proof the registry contains that image. Never deploy `build-required` or reuse a mutable version tag for changed content.

The farm01 namespace, DB and role are `agentboard`. The dedicated CNPG Cluster keeps two instances, 20Gi and the selected `local-path-cnpg` class, SCRAM/TLS-only access, and the confirmed PostgreSQL 18.6 image pin. CNPG's generated `agentboard-db-ca` Secret provides `ca.crt`, mounted read-only in app and migration containers at `/etc/agentboard/db-ca/ca.crt`. Postgrex verifies certificate and hostname using this CA. DATABASE_URL, when supplied, overrides split DB connection fields; DATABASE_CA_FILE remains the trust setting. Packaged startup refuses a DATABASE_URL that disables TLS verification (`ssl=false` or `sslmode=disable/allow/prefer`) and fails without disclosing credentials. Credentials stay server-side. [CNPG certificate documentation](https://cloudnative-pg.io/docs/1.28/certificates/) describes the generated CA secret.

Provision app/database/pull secret references out-of-band; never commit or print their values. The app secret contains `secret-key-base` and optional `database-url`; CNPG bootstrap uses `agentboard-db-credentials` username/password. The CA Secret comes from CNPG, not a copied credential template. Retain sync waves: configuration -2, CNPG -1, additive migration Sync hook 0, app 1. Migration overrides PHX_SERVER=false; application probes `/health/live` and `/health/ready` on port 4000. Do not run application migrations from the CLI.

[Merged companion GitOps PR #152](https://github.com/carverauto/gitops/pull/152) supplies `agentboard-http`/`agentboard-https` on `farm01-edge/farm01-gateway`, `agentboard-tls` from a dedicated exact-host Certificate, and scoped cert-manager/external-dns settings. App HTTPRoutes in this repository reference those sections for `agentboard.farm01.carverauto.dev`, with a 301 HTTPS redirect. The private Gateway is shared; discover its current reconciled address. Preserve all unrelated listeners, solvers, filters, ACME credentials, TXT owner and upsert-only policy. DNS01 works without public HTTP reachability.

Before operator-authorized rollout, provision the **`local-path-cnpg` StorageClass** (the farm01 local-path provisioner with Retain and WaitForFirstConsumer) without silently substituting another class, configure workflow/registry credentials, publish the reviewed image, and prepare out-of-band runtime secrets. Merge/apply the reviewed companion edge through its established operator procedure. Then verify CNPG/PVC/migration readiness, Certificate Ready, listener Accepted/Programmed/ResolvedRefs, HTTPRoute Accepted/ResolvedRefs, private DNS, DNS-only Cloudflare records, verified HTTPS/hostname and HTTP redirect. Verify the trusted-network boundary before exposing the unauthenticated v1 API.

Worker machines need only private API reachability, AGENTBOARD_URL and HTTPS trust. Publicly trusted cert-manager certificates use the system roots; private issuer deployments additionally configure AGENTBOARD_CA_FILE. No CLI host needs CNPG trust or database passwords. Loopback HTTP is reserved for isolated development/tests.

Smoke `agentboard meta`, two distinct harness registrations, one task, concurrent claim conflict, attributed progress, explicit renewal, heartbeat, handoff/inbox acknowledgement and quota snapshots after infrastructure readiness. Record actual results in [verification evidence](verification.md). The isolated acceptance already covers these contracts but cannot prove the live storage/operator/image/network path.

Rollback the application to a previously compatible immutable digest, retaining additive schema and data. Down migrations reject destructive reversal. If this is the first deployment and no compatible app exists, stop traffic and fix forward. Remove only agentboard edge resources when intentionally retiring its traffic; never delete shared Gateway/wildcard TLS or board history. Upsert-only leaves DNS cleanup to the operator.

The CLI executable is `agentboard` (ApacheBench already owns `ab`). Download the platform asset and SHA256SUMS from the release, verify the checksum, then install it as `~/.local/bin/agentboard`; this directory should be on PATH. Darwin runtime validation is recorded separately in the rollout evidence.
